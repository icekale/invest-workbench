# 个人投资研究工作台 · 设计规格

日期：2026-09-07  
状态：待用户审阅后进入实现计划

## 1. 目标

做一个**单人使用**的投资研究工作台，可部署到 VPS。第一期是可运行的 TDesign Vue 应用：页面齐全、模拟持仓与研究数据，**股票/ETF 价格与指数走腾讯行情**。

不是再做一个拾光研选。拾光贡献两件事：公募研究功能形态，以及页面气质（白底、大标题、圆角卡片、克制灰）。

## 2. 已锁定的决定

| 项 | 决定 |
|---|---|
| 技术 | TDesign Vue Next Starter（Vue 3 + Vite + Pinia + TypeScript） |
| 视觉 | TDesign 做壳（布局、路由、登录）；页面皮肤对标拾光研选 |
| 用户 | 单用户；需要登录页（VPS）；无注册、无角色权限 |
| 账户 | 股票账户 + ETF 账户，**同一套指标**，驾驶舱里两个独立板块 |
| 驾驶舱布局 | 合计 KPI → 股票 \| ETF 并排 → 每日宏观 \| 机会池 |
| 公募研究 | 独立第 2 页，对标拾光：智能组合 / 优质精选 / 基金数据 |
| 行情 | 腾讯行情拉股票、ETF、指数现价；持仓市值/盈亏用现价算 |
| 第一期不做 | 券商同步、真实量化模型、多用户、多语言 |

## 3. 信息架构

侧栏四项：

1. **投资驾驶舱** `/dashboard`
2. **公募研究** `/funds`
3. **计划与执行** `/plan`
4. **持有与复盘** `/review`

登录 `/login`，通过后进驾驶舱。未登录访问其它路由回登录。

### 3.1 投资驾驶舱

从上到下：

1. **合计一行**：两账户成本合计、市值合计、浮动盈亏合计。
2. **股票账户 | ETF 账户**（并排，结构相同）：
   - 持仓成本、持仓市值、浮动盈亏
   - 资产配置（该账户内饼图/条）
   - 持仓健康度（模拟标签：健康 / 观察 / 预警）
   - 持仓买卖点（模拟标签：持有 / 可加 / 减仓 / 退出）
   - 持仓表：代码、名称、数量、成本、现价、市值、盈亏、健康度、买卖点
3. **每日宏观 | 机会池**
   - 宏观：上证/深成/创业板/沪深300 等指数点位（腾讯行情）+ 几条模拟简报
   - 机会池：模拟候选列表，列收益/波动/回撤，点击进基金详情

市值、现价、浮动盈亏：`现价来自腾讯行情`，数量和成本价来自本地持仓数据。行情失败时表格仍显示成本侧，现价/市值标「行情暂不可用」，不空白死页。

### 3.2 公募研究 `/funds`

三个 Tab，功能对标 https://www.sglcai.com ：

| Tab | 内容 |
|---|---|
| 智能组合 | 若干风险偏好组合卡片（模拟持仓配比），点进组合详情 |
| 优质精选 | 按类型分类的基金卡；筛选 UI（类型、评级、回撤上限）即时过滤本地列表 |
| 基金数据 | 搜索代码/名称/经理；表列收益、波动、回撤、量化评分，可排序 |

另：基金详情 `/funds/:code`、对比 `/funds/compare`（最多 2–4 只）、备选池（本地收藏）。

**数据边界：** 列表、评分、收益/波动/回撤、组合配比第一期用本地 mock。若腾讯能提供该基金净值/涨跌，详情页现价用真的；没有则用 mock 净值。不做拾光那套真实建模。

### 3.3 计划与执行 `/plan`

- **调仓计划**：目标仓位 vs 当前仓位（当前仓位用本地数量 × 腾讯现价）
- **待办买卖**：账户、代码、方向、数量、理由；状态待执行/已执行（本地改状态）
- **纪律检查**：几条固定规则（单票上限、是否在计划内），对当前持仓做勾选式检查，不是风控引擎

### 3.4 持有与复盘 `/review`

- **投资组合**：两账户持仓的配比与盈亏贡献（价格同驾驶舱）
- **论文追踪**：每只持仓一条逻辑，状态：成立 / 观察 / 失效
- **复盘日志**：按日短记录，预置几条；可新增（写 localStorage 即可）

## 4. 视觉

- 壳：TDesign 侧栏 + 顶栏，收敛默认后台装饰（少用紫蓝块、少用运营 Banner）
- 内容区：白底、大标题、灰副标题、大圆角白卡片、细边框
- 涨跌：红涨绿跌（A 股习惯）
- 公募研究列表/卡片密度靠近拾光，不要后台表格堆满一屏控件

## 5. 技术结构

基于 [tdesign-vue-next-starter](https://github.com/Tencent/tdesign-vue-next-starter)：

- 删掉示例仪表盘/列表/详情等无关页，侧栏只留上述四项 + 登录
- 权限系统不用：登录成功视为唯一用户
- 登录：固定账号（规格实现时写在环境变量，如 `VITE_AUTH_USER` / `VITE_AUTH_PASS`，默认 `xiong` / `demo`）；token 放 localStorage
- 状态：Pinia；持仓/计划/论文/日志以 mock 为初值，可写回 localStorage 的仅限：待办状态、备选池、复盘新增、论文状态
- 图表：Starter 已有的图表库，不新增图表依赖

### 5.1 腾讯行情

- 用途：A 股股票、场内 ETF、常用指数的现价、涨跌幅
- 实现：前端（或 Vite 开发代理）请求腾讯行情接口，按代码批量拉
- 刷新：进入驾驶舱/计划/复盘时拉一次；提供手动刷新。不做 WebSocket
- 失败：页面可用，数字位显示「—」和短提示
- 代码格式在实现计划里写死（`sz000001` / `sh510300` 等），本规格只要求「本地持仓代码能映射到腾讯代码」

### 5.2 本地数据（第一期）

预置一份模拟数据，覆盖：

- 股票账户 4–8 只、ETF 账户 4–8 只（含成本、数量、健康度、买卖点、论文）
- 宏观简报 3–5 条
- 机会池 8–12 只
- 智能组合 4–6 套、精选/全市场基金 20–40 只（含模拟收益/波动/回撤/评分）
- 调仓计划、待办、纪律规则、复盘日志各若干条

不接券商持仓接口。改持仓只能改 mock 文件（第一期不做持仓编辑器）。

## 6. 错误与空态

- 行情失败：见 3.1
- 搜索无结果、备选池为空、日志为空：一句话空态，不空白
- 登录失败：账号或密码错误，不泄露是否存在用户（本来就一个用户）

## 7. 测试

第一期不做测试框架。留下一个可运行检查：登录后驾驶舱能渲染两账户，且对至少一个 mock 代码请求腾讯行情（成功显示数字或失败显示「—」）。

## 8. 明确不做（第一期）

- 注册、找回密码、权限、多用户
- 券商/柜台同步、导入交割单
- 拾光量化模型训练与真实全市场基金库
- 银行理财、PWA、广告
- 暗色主题定制（跟随 Starter 默认即可，不作为目标）

## 9. 成功标准

本地 `npm install && npm run dev` 后：

1. 能用固定账号登录
2. 四页都能点开，驾驶舱股票/ETF 并排、同一套指标
3. 公募研究三个 Tab 能筛、能进详情
4. 持仓现价来自腾讯行情（或明确的失败态）
5. 页面气质接近拾光，而不是 TDesign 示例后台
